扫雷叠加器 —— 使用说明
================================================================

双击「扫雷叠加器.exe」启动。它是**单文件 exe**：Python 运行时、Node、
识别引擎全部打包在里面，不需要安装任何东西。
（单文件的代价：每次启动要先自解压，双击后等几秒才出窗口，是正常的。）

----------------------------------------------------------------
怎么用
----------------------------------------------------------------

1. 打开游戏，让棋盘完整显示在屏幕上。

2. 按 F11  → 屏幕会变暗，按住鼠标左键拖一个矩形，把整个棋盘圈进去，
              松开即生效。框太小会被拒绝，重拖一次就行。
              （拖的时候按 Esc 可以取消）

3. 框好之后，模拟器的推断结果会以 25% 不透明度实时叠在棋盘上：
      · 绿底「宝」  = 确定是宝藏，建议挖开
      · 红底「弹」  = 确定是炸弹，别碰
      · 深灰底      = 确定是空地
      · 绿底数字    = 安全格：求解器**证明**了这格不可能是炸弹（只可能是宝藏或空地）。
                      数字是宝藏概率，越大越值得挖。
      · 深红底数字  = 危险格：还有踩雷的可能。数字是炸弹概率，越大越危险。
      · 带颜色边框的数字 = 识别到的游戏提示（方便核对有没有认错）
      · 蓝色外框    = 识别出来的棋盘边界
      · **白框圈住的那一格** = 推荐的下一步（见下一节）

   绿/红的分界线是「炸弹概率是不是恰好为 0」，不是「概率大不大」——
   0 是求解器证明出来的硬边界。扫雷里几乎每个未挖开格都带一点炸弹概率，
   按概率大小分档会退化成"一片全红"，反而看不出东西。

   25% 不透明度下颜色会被游戏底色的橙棕冲淡（这是没法避免的：
   橙棕底本身红通道就高，红色叠上去还是棕）。看着不够清楚就把
   「不透明度 %」调大，60% 以上红绿会非常明显。

4. 按 F12  → 取消框选、收起叠加层，采集也随之停掉。

5. 按 F9  → 开/关「自动挖开推荐格」。开启后程序会自己移动鼠标去点
              白框推荐的格子，点完把鼠标挪到棋盘外，等识别刷新后再点下一格。
              （细节见后面「自动挖掘（F9）」一节）

6. 按 F10  → 把「此刻叠加器看到的那一帧」存下来（见后面「识别不对时」一节）。
              平时用不到，认错了才按。

叠加层是**点击穿透**的，鼠标可以直接穿过它去点游戏；
它也不会出现在自己的截图里，所以不会干扰识别。


----------------------------------------------------------------
推荐下一步（白框那一格）
----------------------------------------------------------------

目标既然是「找齐全部宝藏、步数越少越好」，那每回合该点哪一格是有最优解的。
带白框的格子就是推荐，控制面板里同时会写一行理由。规则是：

  1. **有零风险格就绝不冒险。** 所谓零风险 = 求解器**证明**了这格不可能是炸弹
     （只可能是宝藏或空地）。因为点到炸弹直接结束本局，不是扣分 ——
     所以任何"风险换收益"的算法都是错的，哪怕那格看起来收益很高。
  2. 零风险格里挑 **宝藏概率 + 0.3 × 连锁概率** 最高的。
     · **宝藏概率高** = 这一步很可能直接拿到宝藏，等于没白花一步。
     · **连锁概率高** = 这一步很可能点开一片空地。点空地会**连锁翻开一大片**，
       一次换回一大堆线索；点普通数字格只翻开这一格。两者对步数的影响差着量级。
     · 这两项是"加权"而不是"谁优先"：0.3 这个数是在你的通关盘面上**量出来的**
       （见下面「步数」一节），不是拍脑袋。
     · **两项分数完全一样时**（很常见），再按「未挖开邻格数」多的优先。
       这条看着像无关紧要的细节，其实是**这一版最大的改动**：平局时原来按格子
       从上到下、从左到右的顺序挑，那个顺序纯属任意；而平局里翻出的是哪一格数字，
       会决定后面能不能早点把宝藏推出来。改完之后 18×18 盘面的平均步数
       从 146.7 掉到 123.1（**-16%**）。
  3. **「不可能再有宝藏」的那一片，一律跳过。**
     未知格按 8 邻接分成一块一块。约束是**局部的**（一个已翻开的数字格只约束
     它周围 8 格），所以信息不会从一块流到另一块 —— 某一块里所有格子的
     「宝藏概率」都是 0，这一块就再也翻不出宝藏了，点它纯属白花步。
     而且**只要宝藏还没找齐，就一定存在有宝藏的那一块**（所有未知格的宝藏概率之和
     = 剩余宝藏数 > 0），所以这一步永远不该走 —— 这是硬规则，不是经验。
     （你报的现象就是它：一小片区域显然不会再有宝箱，白框还是往里指。）
  4. 一个零风险格都没有（局面走到死胡同）→ 只能冒险，
     挑**炸弹概率最低**的，并在面板里明确告诉你"这格有 X% 会炸"。

**关于「连锁概率」—— 这里有个坑值得说明白。** 求解器的三态模型是
「宝藏 / 炸弹 / 非道具」，而"非道具"里混着两种东西：**空地**（周围 8 格没有道具，
点开连锁翻一片）和**数字格**（周围有道具，点了只翻一格）。
一块 18×18 的盘上 260 个非道具格里只有 53 个是真空地，另外 207 个都是数字格。
所以"非道具概率高"根本不能拿来当"会连锁"用 —— 那等于在奖励"点到数字格"，
方向正好反了（实测步数反而从 152 涨到 178）。
叠加器算的是单独一项 **P连锁 = 这格和它周围 8 格都不是道具的概率**，那才是"点开会连锁"。

**理由那一行会分四种情况说**，因为它们对步数的意义完全不同：
「确定是宝藏」／「零风险，X% 是宝藏」／「零风险，X% 会连锁翻一片」／
**「零风险，但这格既不出宝藏也不连锁」**。最后这种在残局很常见 ——
活区里剩下的全是"已证明不是道具"的格子，点开它能看到一个数字，
给旁边的未知格补上一条约束。它不是好棋，但比冒险强，也比去翻死区强。

白框是"近黑外圈 + 白内圈"的双环，靠明暗对比，在任何底色上都看得见。
（不能画彩色环：25% 不透明度下彩色会被橙棕底压平，跟绿/红填充也抢色。
也不能用纯黑：叠加层把纯黑抠成透明，画了等于没画。）

面板上还会报「零风险格 N 个 · 需要冒险的格 M 个」，N 大于 0 时说明
这一步是稳的；N 等于 0 时白框那格是迫不得已，点之前想清楚。

----------------------------------------------------------------
步数：实测下来能压到多少
----------------------------------------------------------------

拿你给的三张通关截图还原出完整真值（各 18×18，38 宝藏 / 26 炸弹，
数字提示与布局**零矛盾**），按同样的规则把整局重跑一遍数步数：

    盘面        上一版    现在这版
    第一张      124 步    112 步
    第二张      101 步    101 步
    第三张      115 步    108 步

两块盘面毕竟只是样本，所以另外造了两组**各 80 块**同参数的随机盘面
（18×18 / 38 宝藏 / 26 炸弹，从零开局，固定种子，盘面已冻结在
 叠加器/自检/基准盘面_18x18_80块.json），逐块跑完整局：

    甲组 80 块    123.1 步 → 116.8 步
    乙组 80 块    123.9 步 → 115.6 步

**这一版改了什么，值多少步：**

  · 跳过「不可能再有宝藏」的区域（上面第 3 条）：**-7.1 步（甲）/ -7.8 步（乙）**，
    也就是 -5.8% / -6.3%。这是**配对比较**的结果（只比两边都跑完的同一批盘面）：
    甲组 39 块变好、2 块变差、16 块持平；乙组 47 块变好、0 块变差、15 块持平。
    踩雷次数一格没变。
  · 平局时优先「未挖开邻格多」的格：约 -16%（上一版做的，见下）。

**关于第一步保护**：你说了这是基本规则，所以模拟器也照做 —— 第一手点到的位置
如果是炸弹，炸弹被挪到别处、数字跟着重算。它**不改变步数**（两边都跑完的盘面上
逐块一模一样），只是把"第 1 步踩雷"这种不该算的死法改掉了：80 块里救回 7 次 / 4 次，
其中 4 块 / 3 块因此能通关。之前那份"每 80 块踩雷 27 次"里的第一步那几次是模型错了。

求解速度：真值盘面上中位数 0.6~1.0ms，但**尾部长** —— 第一张/第二张最慢 4ms / 16ms，
第三张有几步要 60~126ms（那一局有超大的约束块，得靠抽样兜底）。
叠加器是"画面变了才算一次"，这种偶发的 100ms 停顿不碍事，但要知道它存在。

**上一版说"离偷看答案只差 2 步、该停手了"—— 那个说法是错的。**
那个"偷看答案"的策略（`oracleBest`）只是**另一种贪心**：每一步挑眼前最值的那格，
它自己也有平局次序、也会瞎挑。现在这版引擎在配对比下**反超它 3.5 步（甲）/ 7.0 步（乙）**，
说明它根本不构成上界。也就是说目前**没有一个可信的天花板**可参照，
"还差多少步"这件事现在答不出来 —— 要么接受现状，要么去做多步前瞻
（为了两步后的局面主动走一步现在看着一般的棋），那是另一个量级的改动。

（连锁概率的权重 0.3 是在真值盘面上扫出来的：0.05 到 0.5 之间结果都是 125 步，
平台很宽，取中间值。跨密度的稳健性另有两份测试，见 叠加器/调权重.js
和 叠加器/基准18.js。）


----------------------------------------------------------------
自动挖掘（F9）
----------------------------------------------------------------

按 F9（或勾选面板上的「自动挖开推荐格」）开启。开启后叠加器会自己玩：

  · 每当识别刷新、且推荐格（白框）有变化，就像真人一样点那一下：
    落点带 ±3px 抖动，移动分两段"先到附近再滑进格子"，落定停约 0.4 秒，
    按下保持约 0.16 秒再弹起，弹起后再等约 0.35 秒才把鼠标挪走 ——
    完整的"移动 → 按下 → 弹起"，节奏按人手来，每段间隔都带随机浮动
    （真实游戏拒收又快又准的机器点击）。
  · 点完立刻把鼠标挪到棋盘外最近的一侧。这不是多余的：鼠标压在
    格子上，那一格的读数会被「悬停保持」冻住（见下），指纹不变，
    自动挖掘就走不到下一步。
  · 限流与重试：距上次点击至少 0.8 秒；如果点击后棋盘没变化
    （没点中 / 游戏不认合成点击 / 窗口被挡住），隔 2.5 秒自动重试，
    连试 3 次仍没变化就自动关掉 F9 并提示 —— 不会隔着旧局面无限乱点。
  · 每次点击前都会核对推荐格位置下的窗口：游戏窗口被挪走/被盖住时
    不下键，宁可停下来提示。

注意事项：

  · 开启后**鼠标会被程序接管**。想自己操作，再按一下 F9 关掉。
  · 残局没有零风险格时，推荐格本身会带炸弹概率（面板里写了百分比），
    自动挖掘照样会去点 —— 等于接受"迫不得已的冒险"。不想赌就关掉。
  · 自动挖掘开着时不要动鼠标去抢，两边的点击会互相打架。
  · **找齐自动收工**：识别到的已挖开宝藏达到设定的宝藏总数（默认 38）时，
    程序自动停掉自动挖掘、清除框选，状态栏提示收工。开新局按 F11 重框即可。

**悬停保持**（顺带说明）：鼠标停在某个格子上时，那一格的识别读数会被
冻结在"悬停前"的值上 —— 游戏悬停时会给格子加高亮，未挖开格上印着的
淡淡兔子水印会被误认成"已挖开的宝藏"，把整个棋盘带得重算一遍。
鼠标挪开，读数立即恢复实时识别。


----------------------------------------------------------------
参数（控制面板）
----------------------------------------------------------------

  棋盘边长（识别用）   默认 18    数不出格线时按这个均分；能数出来就以实际为准
  宝藏总数            默认 38
  炸弹总数            默认 26
  不透明度 %          默认 25    改完立刻生效
  刷新间隔 ms         默认 350   调小更跟手，调大更省 CPU

  「暂停刷新」勾上就停止截图识别，方便你静止观察。

出问题了怎么办
----------------------------------------------------------------

日志在：%LOCALAPPDATA%\扫雷叠加器\overlay.log
（在资源管理器地址栏粘这一行就能打开）

----------------------------------------------------------------
识别不对时：按 F10 存现场
----------------------------------------------------------------

「识别偶发不对、重框一次又好了」这类问题，光靠描述是查不动的 ——
得看**当时那一帧的原始像素**到底长什么样。所以：

  觉得认错了的那一刻，**先别重框**，直接按 F10。

F10 会在程序所在目录下的「存证」子目录里存两个文件（同一时间戳）：

  异常_20260925_013045_手动.png     ← 叠加器当时看到的画面（原样像素）
  异常_20260925_013045_手动.json    ← 同一张图的完整诊断

为什么要"先别重框"：一按 F12 / 重框，那一帧的现场就没了，
再复现得靠运气。F10 是按一下就存，不影响你继续操作。

另外，下面两种情况程序会**自动**存一次现场，不用你按：

  · 识别**失败**（状态栏报错 / 叠加层顶上出现红色警示带）
  · 识别成功但**棋盘尺寸不对**（状态栏出现 ⚠ 那一条）

自动存证有限流（20 秒内最多一次、一次框选最多 8 次），免得一直坏就一直写盘。

存的 JSON 里有：框选范围、当时的参数（宝藏数/炸弹数/棋盘边长）、
用同一张图重跑一遍识别的完整 debug 输出（格线位置、颜色分档、
逐格亮度与字形、求解结论）。排查时把这两个文件发我即可。

存证目录在哪：和 exe 同一个文件夹下的「存证\」。
如果那里不可写（比如放在只读位置），会退到
%LOCALAPPDATA%\扫雷叠加器\存证\。

也可以直接点界面上的「存下这一帧 (F10)」按钮，和按 F10 一样。

常见情况：

· 双击没反应
    看上面的日志。启动失败会同时弹一个错误框，把里面的内容发我。

· 叠加层位置偏了 / 框选的位置和实际不吻合
    屏幕缩放不是 100% 时最容易出现。程序会自己声明 DPI 感知，
    正常情况不该偏。真偏了告诉我缩放比例。

· 状态栏显示「⚠ 识别到的棋盘是 AxB，与设定边长 N 不符」
    意思是：格线没对准 —— 识别出来的棋盘比你要的小/大（比如 18×18 认成 17×18）。
    这时叠加的绿红会整体错位一格，看着"就是不太对"。

    **这种情况程序会自动存证**（帧图 + 诊断 JSON 进「存证」目录），
    不用你按 F10。先按 F12 重框一次，一般就好了；
    如果反复出现，把「存证」里最新的那对文件发我。

· 状态栏显示「求解未通过：...」，叠加层顶部有一条红色警示带
    说明识别到的提示互相矛盾 —— 通常是某一格数字认错了。
    把鼠标移开、让游戏画面稳定一下；还不行就按 F12 重框一次。
    红色带里的原文就是具体哪一格出的问题，发我可以定位。

· 提示「没找到棋盘格线」
    框选范围没对准棋盘，或者格线太淡 / 棋盘在画面里太小。重框一次。

· Windows 弹出「已保护你的电脑」/ SmartScreen 警告
    因为这个 exe 没有代码签名。点「更多信息」→「仍要运行」即可。
    不放心的话可以自己用 叠加器exe\构建.py 重新构建一份。

· Windows Defender 报 Trojan:Win32/Bearfoos.A!ml（或 Wacatac.B!ml 之类）
    这是**误报**，不是真中毒。

    原因很明确：这个 exe 是 PyInstaller 打包的 Python 程序，没有代码签名。
    Defender 的机器学习启发式（名字里的 !ml 就是 Machine Learning 的意思，
    不是特征码命中）对"未签名 + 打包器产物"这类文件误判率一直很高，
    PyInstaller / Nuitka 的产物被批量误报是长期存在的问题。
    程序本身**不联网、不上传任何数据**，全部源码就在旁边的
    叠加器\ 目录和 扫雷模拟器.html 里，可以直接看。

    已经做过的缓解：
      · exe 里填了完整的版本资源（右键属性 → 详细信息，公司/产品/版本都能看到）
      · 构建时显式关掉 UPX 压缩壳（加壳会显著抬高 ML 评分）
      · 带图标（没有图标的裸 exe 也是加分项）

    如果还是被拦，三个办法任选：

      1) 把整个文件夹加进 Defender 排除项（最省事，需要管理员权限）
         开始菜单搜 PowerShell → 右键「以管理员身份运行」，粘这一行：
           Add-MpPreference -ExclusionPath "C:\Users\JIIM\Desktop\simulator\扫雷叠加器"
         撤销就把 Add- 改成 Remove-。

      2) 报给微软走误报申诉（免费，通常一两天有结果，治本）
           https://www.microsoft.com/en-us/wdsi/filesubmission
         选「I believe this file is incorrectly detected」，把 exe 传上去。

      3) 干脆不用 exe：直接用 Python 跑 叠加器\overlay.py，
         或者自己用 叠加器exe\构建.py 在本机重新构建一份（本机构建出来的
         不会被本机 Defender 认成"陌生文件"）。

    **不要**为了这个直接关掉实时保护。


----------------------------------------------------------------
这个文件夹里是什么
----------------------------------------------------------------

  扫雷叠加器.exe     主程序，双击它。单文件版：Python 运行时、随包的
                     Node（识别和求解跑在这上面）、识别引擎全部在 exe 里，
                     启动时自解压到临时目录（所以冷启动慢几秒）。
  使用说明.txt       就是这份文件
  存证\              按 F10 存的现场（帧图 + 诊断 JSON）。可以随时清空。
                     这个目录是程序自己建的，删掉也行，下次按 F10 会重新建。

源码与构建（在这份交付的上一级目录 simulator\ 里）：

  叠加器\            最小源码：overlay.py（主程序）、bridge.js（引擎桥）、
                     engine_core.js（从 扫雷模拟器.html 抽出的识别+求解引擎）、
                     templates.json（字形模板）。
  叠加器exe\         构建这套 exe 所需的全部：构建脚本、启动入口、node.exe、
                     图标、版本资源。跑「python 叠加器exe\构建.py」即可重建 exe。

**拷走时把 exe 和使用说明一起拿走就行（单文件，不挑位置）。**

----------------------------------------------------------------
自检（出问题时用得上）
----------------------------------------------------------------

在文件夹里按住 Shift 右键 →「在此处打开 PowerShell 窗口」，然后：

  .\扫雷叠加器.exe --selftest "某张棋盘截图.png"

它不开窗口，直接把 node / 引擎 / 模板 / 识别 / 求解整条链路走一遍，
结果会写进上面那个日志文件。用来判断是环境问题还是识别问题。
